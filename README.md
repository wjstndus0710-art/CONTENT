# 콘텐츠 스튜디오

콘텐츠 제목, 채널, 제작 상태, 발행일, 반복 주기와 메모를 관리하는 한국어 웹앱입니다. 대시보드, 제목 검색, 상태 필터, 등록·수정·삭제를 제공합니다.

## 실행

Node.js 24 이상이 필요합니다. 외부 npm 의존성 없이 실행됩니다.

```sh
cd /workspace/CONTENT
npm start
```

기본 포트는 3000이며 `PORT` 환경 변수로 변경할 수 있습니다. 데이터는 `data/content.sqlite`에 저장되며 서버 재시작 후에도 유지됩니다. `npm test`로 API 검증을 실행합니다.

반복 주기는 관리용 정보이며 후속 콘텐츠 자동 생성이나 실제 채널 자동 발행을 수행하지 않습니다. 이번 주 지표는 한국 시간 기준 오늘부터 7일 동안의 미발행 콘텐츠입니다.

개인용 단일 계정 버전입니다. `APP_PASSWORD`를 설정하면 화면과 모든 데이터 API가 브라우저 기본 인증으로 보호됩니다. 운영 모드에서는 12자 이상 비밀번호가 없으면 서버 시작을 거부합니다. 사용자별 데이터 분리는 없습니다. HTTPS와 영구 저장공간을 갖춘 배포 방법은 [DEPLOYMENT.md](DEPLOYMENT.md)를 참고하세요. SQLite 파일은 개발 환경 내부 저장소이며 별도 백업 없이 환경을 삭제하면 데이터가 사라질 수 있습니다.

## 엑셀 기반 관리

- 운영 현황: 사업부, 주제, 메인·서브 키워드, 네이버 노출, 담당자와 5개 채널별 상태를 입력합니다.
- 캘린더: 원문 발행일 기준으로 월간 일정을 보여줍니다. 날짜가 없는 콘텐츠는 운영 현황에서 관리합니다.
- 채널별 발행: 콘텐츠 ID, 채널별 제목·키워드·형태·날짜·URL·상태를 관리합니다.
- 키워드 관리: 네이버·Google·AI 노출, 기존 콘텐츠 여부와 신규 작성 필요를 기록합니다.
- 마케팅 일지: 주 단위(월~금, 필요하면 주말 포함)로 요일별 할 일을 적고 완료한 일을 체크합니다. 주마다 목표·메모를 남길 수 있고, 검색창에서 지난 일지의 할 일을 찾아 해당 주로 이동할 수 있습니다. 할 일은 하루 100개, 한 줄 500자까지 저장됩니다.
- 상단의 백업 내려받기는 현재 기록과 가져온 원본 시트 전체를 JSON으로 내려받습니다. 상단의 백업 복원으로 빈 서버에 JSON을 복원할 수 있습니다. 기존 데이터가 있는 서버에서는 덮어쓰기를 거부합니다. SQLite 파일을 별도로 보관하면 전체 DB를 복원할 수 있습니다.

엑셀 가져오기(시트 이름과 열 구조가 첨부된 콘텐츠 캘린더와 같은 파일):

```sh
npm run import:xlsx -- '/절대/경로/콘텐츠 캘린더.xlsx'
```

월별 마케팅 일지 시트(`Weekly To Do (N월M주차)` 행 아래에 요일별 할 일을 적은 시트, 예: `2026"10`)도 함께 가져옵니다. 날짜 행의 월~일 열(B~H)과 바로 아래 행의 내용을 같은 날짜로 묶고, 셀의 각 줄을 할 일 하나로 나눕니다(`- `, `1. ` 같은 목록 기호는 지웁니다). A열 내용은 그 주의 목표·메모가 됩니다. 엑셀에는 완료 표시가 없으므로 가져온 할 일은 모두 미완료 상태로 시작합니다. 앱에서 이미 쓴 날짜가 있으면 덮어쓰지 않고 새 할 일만 뒤에 추가합니다. 운영 현황 시트에서는 앱에 같은 제목이 이미 있는 콘텐츠를 건너뛰므로, 개정된 엑셀을 다시 가져와도 기존 콘텐츠가 중복되지 않고 새 콘텐츠만 추가됩니다. 채널별 발행·키워드 시트가 없는 파일도 가져올 수 있습니다.

Node.js 24 및 Python 3 표준 라이브러리만 사용합니다. 가져오기 전 DB를 `data/backups`에 백업하고 원본 파일을 `data/imports`에 보관합니다. 원본 운영 현황의 제목 있는 행만 콘텐츠로 가져오며, 사본과 자동 연동 캘린더는 중복 등록하지 않습니다. 모든 시트의 원본 값은 DB와 백업 JSON에 보존합니다. 파일 SHA-256와 시트 행을 기준으로 같은 파일 재실행은 건너뛰며, 기존 수정 내용을 덮어쓰지 않습니다. **내용이 달라진 파일은 별도 가져오기로 취급합니다. 이미 있는 콘텐츠 제목과 일지 할 일은 건너뛰지만, 기존 기록의 수정 내용을 엑셀 값으로 갱신하지는 않습니다.**

원문 채널이 네이버 블로그이면 해당 채널 상태에서 원문 상태를 매핑하고, 그 외 확인할 원문 상태가 없으면 ‘발행 확인 필요’를 표시합니다. 발행일만으로 발행 완료를 추정하지 않습니다. 엑셀 진행률은 원본으로 보존하며, 앱 완료율은 네이버·홈페이지·티스토리·카카오·인스타 5개 채널의 발행완료 수로 계산합니다. 숫자 `38` 등 원본에 있는 값은 그대로 보존합니다. 반복 주기가 엑셀에 없으므로 모든 가져온 콘텐츠는 미설정으로 시작합니다.

채널별 발행과 키워드 시트의 `콘텐츠 ID`는 원본 텍스트로 유지됩니다. 운영 현황에는 같은 ID가 없으므로 서로 자동 연동되지 않습니다. 각 화면의 변경은 해당 기록에만 적용됩니다.

테스트에 사용하는 `test/fixtures/calendar.xlsx`와 `test/fixtures/journal.xlsx`는 실제 업무 데이터 대신 가상 데이터를 넣은 구조 검증용 파일입니다.
